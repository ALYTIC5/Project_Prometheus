# Concept-art -> sprite-atlas pipeline

Turns the hand-painted JPEG concept sheets in `Mockups/` into
`frontend/src/sprites/{manifest.production.json, sprite_palette.json,
*_atlas.png}`, matching the existing `AtlasSpec` schema in
`frontend/src/sprites/registry.ts` exactly. `sprite_palette.json` is a
separate file from the renderer's hand-authored `palette.json` (read by
`frontend/src/render/*.ts` via `palette.ts`) -- never overwrite that one.
No renderer files are ever
touched by this pipeline.

## The real sequence

```
recover_alpha -> slice_sheets -> manual_crops -> HUMAN edits overrides.json
              -> normalize_scale -> compute_anchors -> build_palette
              -> pack_atlas -> verify_atlas
```

`manual_crops.py` handles the specific, identified case connected-component
slicing cannot: a handful of renders on these sheets are drawn touching
their neighbour or the panel border with *zero* pixel gap (confirmed with
morphological opening tests up to a 6px radius -- not a thin bridge a
bigger erosion would separate, genuine 2D contact). Its `CROPS` list is
hand-determined bounding boxes against each `Mockups/BATCH 0N.jpg`; rerun
it after `slice_sheets` and before naming.

`normalize_scale` cannot infer a building's footprint class (or a
character's role) without knowing its kind, and it cannot know its kind
without a name. Any sprite still `name: null` in `overrides.json` is
skipped with a warning, and the run fails at the end listing every skip.
**That is the intended checkpoint on a fresh checkout, not a bug** --
`make art-slice` stops there on purpose so a human can do the one
irreplaceable step before `make art-build` continues.

Every stage is invoked as `python -m tools.art.<name>` from the repo
root (paths resolve via `Path(__file__).resolve().parents[2]`, so this
works from any cwd, but the Makefile and this doc both assume repo
root).

## Running it

```
make art-slice
# -> edit art/sliced/overrides.json: set "name" for every sprite you
#    want kept, "-" to discard it. Open art/sliced/contact_sheet.html
#    in a browser while you do this.
make art-build
```

`make art-verify` re-runs just the last check. `make art-clean` wipes
regenerable intermediates (`art/recovered`, `art/scaled`, `art/anchored`,
`art/review`) but **never deletes `art/sliced/overrides.json`** -- that
file holds every naming and anchor decision a human made and is the only
thing in this pipeline that cannot be regenerated by rerunning a script.

On Windows this all assumes Git Bash (the repo already assumes it for
shell work elsewhere). PowerShell equivalent for `art-clean`:

```powershell
Remove-Item -Recurse -Force art\recovered, art\scaled, art\anchored, art\review -ErrorAction SilentlyContinue
Get-ChildItem art\sliced -File | Where-Object Name -ne 'overrides.json' | Remove-Item -Force
```

## `overrides.json` naming convention

This is the one human-edit file. It is read-merged-rewritten on every
rerun of `slice_sheets`: new sprite ids get `name: null` appended, ids
that vanish keep their entry (marked `stale: true`) rather than being
deleted, and a human-entered `name` or `anchor` is never overwritten.

| Category | `name` form | Example |
|---|---|---|
| building | `{kind}_{phase}` | `library_damaged` |
| monument tier | `monument_tier_{short\|standard\|tall\|extreme\|base}` | `monument_tier_tall` |
| agent | `{role}_{action}_{f\|b}` | `builder_work_f` |
| agent filmstrip | same + `@{frames}` | `engineer_walk_f@8` |
| terrain | `terrain_{label}` | `terrain_grass` |
| prop | `prop_{label}` | `prop_torch` |
| effect strip | `fx_{label}@{frames}` | `fx_beacon_fire@6` |
| discard | `-` | excluded from every later stage |

`kind` must be one of the 7 art-covered building kinds
(`temple, monument, watchtower, library, forge, arena, oracle`) and
`phase` one of the 7 `ConstructionPhase` values
(`planned, scaffolding, foundation, active, damaged, sealed, overgrown`).
`role` must be one of the 4 art-covered agent roles
(`builder, scribe, engineer, experimenter`) and `action` one of the 4
legal `AgentAction` values (`idle, walk, work, carry`) -- **this is
where sheet labels like "Reading"/"Hammering"/"CarryingScroll" get
collapsed by a human onto those 4 legal values**. No script infers this
mapping; `pack_atlas.py` hard-rejects any agent name whose action segment
isn't one of the 4, naming the offending sprite id so it's easy to find
and fix.

Filmstrip frames all share one scale factor (computed from frame 0) so
the animation doesn't pulse; give every frame of one animation the same
base name + `@N` and let `normalize_scale` handle the rest.

## Known limitations (by design, not oversight)

- **Checkerboard tolerance is a per-sheet judgement call.** JPEG ringing
  smears real edges toward the background colour, and soft drop shadows
  under a tile locally darken the checkerboard -- there is no single
  global tolerance that is simultaneously perfect everywhere on every
  sheet. `recover_alpha.py --tolerance` exists for exactly this; retune
  per sheet after reviewing the magenta-composited output.
- **Some sheets render multiple panels at slightly different checker
  contrast** (confirmed on `Mockups/BATCH 01.jpg`: the terrain-tile panel
  is measurably lower-contrast than the props panel). `detect_checkerboard`
  now samples multiple spatially-distinct high-amplitude colour pairs
  and classifies against all of them, but an unusually low-contrast
  third panel could still need a manual `--tolerance` bump.
- **Frame/border/divider chrome removal (`strip_frame_components`) can
  delete real content, not just chrome.** It works by removing a whole
  connected component when its bounding box is implausibly large for a
  single sprite and its fill ratio is low -- correct for the actual
  header/border/divider lines, but if a real sprite sits flush against
  that same line (touching the panel edge with no gap), it gets pulled
  into the same component and deleted with it. **Confirmed on this
  project's own sheet 1**: the beach/dock/cliff row sits flush against
  the terrain panel's bottom edge and was entirely erased by this step.
  `recover_alpha.py --no-strip-frame` disables it for one sheet; there is
  no fully-automatic way to tell "chrome" from "content touching chrome"
  apart, so **always check the contact sheet against the source JPEG**
  after slicing, not just for merges but for content that went missing
  entirely.
- **Frame edges can still bridge otherwise-separate sprites** into one
  connected blob even with the above enabled, when `strip_frame_components`
  correctly declines to remove a component (e.g. its fill ratio is too
  high) rather than making a bad guess. `slice_sheets.py`'s
  `sprites.json.rejected` and each sprite's `components_merged` count
  make an unusually large merge visible; the contact sheet makes it
  obvious by eye. There is no fully-automatic fix for this -- it is the
  human review step's job.
- **Off-schema art** (watchtower Observation/Warning/Critical states,
  Oracle's 6 Judgement States, monument height tiers) has no
  `ConstructionPhase`/`AgentAction` equivalent. It gets packed and keyed
  under its own literal name (e.g. `watchtower_state_warning`), tracked
  under `pack_report.json.off_schema_extras`, and is unreachable through
  `resolveSprite()`/`resolveAgentSprite()` today -- that's fine, no new
  schema was invented to accommodate it.
- **The animation-strip layout contract is this pipeline's one
  unverifiable assumption.** `manifest.production.json`'s `frame` for an
  animated sprite is frame 0's rect (`width` = one frame's width), plus
  `frameCount`/`fps`; the renderer is assumed to read `frameCount`
  contiguous frames of that width starting there. `render/*.ts` is
  off-limits to this pipeline, so this can't be verified from this side.
  If wrong, only animated sprites break, and the fix is a one-line change
  in `pack_atlas.py`'s packing shape.
- **`resolveSprite()` short-circuits `kind === 'monument'`** to
  `MANIFEST.ACTIVE` before ever consulting the production manifest, so
  every `monument_*` manifest key is currently dead code. Emitted anyway
  since the art exists; `render/monument.ts` is the presumed future
  consumer.
- **Zero-art building kinds** (`harbour, vault, treasury, archive,
  underworld`) intentionally get **no** manifest entries at all and keep
  rendering procedurally forever -- `verify_atlas.py` actively fails if
  one of them ever gains an entry, since that's exactly the inverted bug
  the retired `tools/verify_atlas.py` had (it demanded full coverage for
  all 12 kinds instead of just the 7 with real art).
