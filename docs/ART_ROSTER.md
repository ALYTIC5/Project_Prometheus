## Critical finding: most characters no longer exist in the PixelLab account

`get_character(id)` (free) was called for all 38 mockup characters. Result:

| Group | Total | Exists in account | Not found |
|---|---|---|---|
| agent-sprites | 12 | **12** | 0 |
| god-sprites | 12 | 0 | **12** |
| harbour-sprites | 3 | **3** | 0 |
| hero-sprites | 11 | 0 | **11** |
| **Total** | **38** | **15** | **23** |

All 12 gods and all 11 heroes are gone — `animate_character` (W4's walk
cycles) cannot target them at all; the only path forward for those 23 is
full recreation via `create_character`, a much larger spend than
animating an existing character. Only the 12 agents and 3 harbour
characters can be animated as-is today.

**Trigger to re-check:** if the PixelLab token is ever rotated to a
different account (see the pause-and-resume protocol's own account
verification step), re-run this check immediately — a different account
would show ALL 38 as not-found, which is a different problem (wrong
account) than this one (same account, characters evicted/expired,
consistent with a trial-tier retention limit: the god-sprites and
hero-sprites batches are the two OLDEST export timestamps in
`Mockups.zip`, both earlier than the still-present agent-sprites batch).

## Second finding: two harbour characters duplicate an agent's prompt verbatim

`harbor_courier`'s own `metadata.json` prompt is word-for-word
`agent_messenger`'s prompt ("Fast fantasy messenger carrying a sealed
research scroll between buildings..."). `harbor_guard`'s prompt is
word-for-word `agent_guardian`'s ("Sturdy fantasy security guardian
enforcing research safety rules..."). Different `character_id`s (real,
separate PixelLab generations), same prompt text — a copy-paste mistake
when the harbour batch was originally commissioned, not a duplicate
record. `harbor_trader`'s prompt is genuinely distinct ("Fantasy harbor
operator responsible for paper-trading execution...").

**Trigger:** before relying on `harbor_courier`/`harbor_guard` as visually
distinct from their agent counterparts in-world, regenerate them with a
real sailor/dockhand-specific prompt (costs `create_character`
generations — bundle with W4's "missing roles" batch, item below).

## Gaps

Confirmed against `prometheus/world/entities.py`'s real `AgentRole` enum
(10 values: `builder, scribe, engineer, experimenter, statistician,
guardian, auditor, necromancer, scholar, prophet`) and the mockup roster
above — three distinct kinds of gap, not one:

1. **Expected gaps, per the World Track prompt's own text (confirmed real):**
   - `builder` — an `AgentRole` value exists in the backend, but no
     `agent_builder` mockup was ever created. W4 Part A creates this one.
   - 3 ambient townsfolk (`townsfolk_villager`, `townsfolk_merchant`,
     `townsfolk_pilgrim`) — cosmetic-only, no `AgentRole` needed by
     design (Law W2). W4 Part A creates these.
   - `dockhand` — a harbour NPC, no `AgentRole` needed. W4 Part A creates
     this one.

2. **New gap found here, not in the original prompt text:** three mockup
   characters exist (`agent_blacksmith`, `agent_historian`,
   `agent_messenger`) with **no corresponding `AgentRole` enum value** in
   `prometheus/world/entities.py` today. They render fine as static art
   but have no real backend agent instance to attach to yet — same
   "built ahead of the data that would drive it" pattern this project
   already documents elsewhere (`docs/DEFERRED.md`'s pathfinding/agent
   entries). **Trigger:** either extend `AgentRole` when a real backend
   concern needs a blacksmith/historian/messenger-shaped agent (e.g. a
   dedicated "carries results between stages" role matching messenger's
   own prompt text), or leave them as decorative-only builder-adjacent
   figures and say so explicitly in the manifest rather than silently
   wiring them to a role that doesn't represent anything real.

3. **The 23-character account-status gap above** — not a "missing
   design," a "missing asset" gap: every god and hero design already
   exists as a real prompt/spec in `Mockups.zip`'s own metadata, it is
   the PixelLab-hosted generation that is gone. Recreating them is a
   `create_character` cost (not a text/design task) — see the Critical
   Finding section above for the trigger.
